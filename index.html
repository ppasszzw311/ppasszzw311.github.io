工程方法（我在專案中的價值）

1. 問題定義

先拆清楚商業需求、資料來源與邊界條件，再設計可驗證的任務分工與里程碑。

2. 系統設計

透過 API 規格、資料模型與流程圖把工程風險前移，避免後期大幅返工。

3. 可維運性

建立一致的錯誤處理、日誌與監控訊號，讓問題可被快速定位與修復。
